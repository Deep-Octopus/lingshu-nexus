# 系统资料补充与导入验收 TODO

> 适用范围：当前 `acupuncture` 针灸领域，优先验证 tVNS/taVNS 资料。
> 当前状态：系统的模拟数据全流程测试已通过，但真实 PDF、真实模型抽取和专家问答效果还没有完成验收。
> 重要说明：把文件复制到仓库的 `paper/` 目录**不会自动导入系统**，仍需在管理页面点击 `Upload` 上传。

## 一、现在优先补充的资料

### P0：真实资料和运行配置

- [ ] **准备首批可使用的 PDF/Markdown 文献**
  - 建议先选 20～50 份有代表性的资料，不要第一次就上传全部文件。
  - 优先包括：指南/共识、系统评价或 Meta 分析、RCT、重要机制研究、安全性或禁忌资料。
  - 优先覆盖：tVNS/taVNS、失眠、抑郁/焦虑、刺激部位、刺激参数、结局指标和不良反应。
  - 确认资料允许用于本项目内部科研处理，并记录来源或授权情况。
  - 扫描版、复杂表格版 PDF 单独放一组，便于统计 OCR 和版面解析问题。

- [ ] **整理一份文献说明表**
  - 每份资料至少记录：文件名、标题、年份、资料类型、主题、优先级、来源链接或数据库、是否允许使用。
  - 可选记录：期刊分区、引用量、高被引/热点标记、备注。
  - 文件名尽量稳定且可识别，例如：`2024_RCT_taVNS_失眠_作者.pdf`。

- [ ] **配置可用的 MiMo 模型信息**
  - 需要：`MIMO_BASE_URL`、`MIMO_MODEL_ID`、`MIMO_API_KEY`。
  - 如抽取模型和聊天模型不同，再补充 `MIMO_EXTRACTION_MODEL_ID`、`MIMO_CHAT_MODEL_ID`。
  - 真实密钥只写入本机 `.env`，不要写入 Markdown、聊天记录或提交到 Git。
  - 没有真实 MiMo 配置时，文件可以解析，但不能完成真实候选知识抽取验收。

- [ ] **确定首批验收问题及期望证据**
  - 建议先选 10～20 个核心问题，不必一次覆盖所有问题。
  - 每个问题补充：期望引用哪些文献/段落；如果资料不足，应回答“证据不足”还是“尚无统一结论”。
  - 优先验证：干预参数、频率差异、安全/禁忌、RCT 设计、结局指标、作用机制和“不得编造统一标准”。

- [ ] **确定审核与发布人员**
  - 至少指定一名专业审核人，负责 `Approve / Modify / Conflict / Reject`。
  - 指定一名管理员，负责最终 `Activate Release` 和必要时回滚。
  - 明确必须重点审核的内容，建议至少包括：刺激参数、禁忌、不良反应、疾病诊断和结论冲突。

### P1：真实效果完善资料

- [ ] **补充领域范围清单**
  - 确认优先疾病/症状、刺激部位、干预方式、参数字段、结局指标和安全信息。
  - 标明哪些内容属于当前版本，哪些内容暂不纳入。

- [ ] **补充术语表和易错映射**
  - 每条包含：标准名称、中文/英文别名、容易混淆的词、是否允许合并、审核备注。
  - 当前已包含耳甲艇、耳甲腔、耳屏，以及 `depression`、`blues`、`Postpartum blues` 等种子词，仍需专家继续补全。

- [ ] **补充证据处理规则**
  - 明确不同文献类型的优先级。
  - 明确多篇论文结论冲突时如何展示。
  - 明确哪些信息只能作为背景，哪些信息可以进入正式发布版本。
  - 当前默认原则是保留原始结论和冲突，不自动合并成统一医学结论。

### P2：需要自动获取新资料时再补

- [ ] **提供外部资料接口契约**
  - 接口地址、认证方式、请求参数、分页/游标规则、调用频率。
  - 一份脱敏的真实请求和返回样例。
  - 返回内容属于 JSON、文件还是下载地址，以及字段含义。
  - 在这些资料到位前，先使用管理页面人工上传即可。

## 二、资料补充和导入流程

- [ ] **第 1 步：小批量准备**
  - 先选 5～10 份文本可复制的 PDF 做第一轮，再加入扫描件和复杂表格文档。
  - 同时完成文献说明表、授权说明和首批验收问题。

- [ ] **第 2 步：配置系统**
  - 执行 `cp .env.example .env`，在本机 `.env` 中填写真实 MiMo 配置。
  - 启动依赖：`docker compose up -d postgres redis minio neo4j`。
  - 启动后端：`make api`；启动前端：`make web-dev`。
  - 访问 `http://localhost:8000/healthz`，应看到 `status: ok` 和 `default_domain_id: acupuncture`。

- [ ] **第 3 步：从管理页面上传**
  - 打开前端页面，进入 `Management`，点击 `Upload`，可一次选择多个 `.pdf`、`.md` 或 `.markdown` 文件。
  - 上传会依次进入：原始文件保存 -> 文档解析 -> MiMo 候选知识抽取 -> 待审核批次。
  - 重复上传同一文件会按内容哈希跳过，不应产生重复正式文档。

- [ ] **第 4 步：检查解析结果**
  - 文档状态应为已解析，`chunk_count` 应大于 0，并能查看页码或段落定位和文本内容。
  - 若失败，记录文件名、失败原因、是否扫描件/复杂表格，并尝试 `Reprocess`。
  - 第一批完成后统计：上传数、解析成功数、失败数和失败类型。

- [ ] **第 5 步：专家审核候选知识**
  - 在 `Review Workbench` 逐条核对原文定位、术语、参数、结局和安全信息。
  - 选择 `Approve`、`Modify`、`Conflict` 或 `Reject`，并填写审核原因。
  - 不确定或来源不足的内容不要直接批准。

- [ ] **第 6 步：创建并激活发布版本**
  - 只选择已批准或已标记冲突的命题。
  - 先执行 `Preview`，检查纳入、排除、新增和删除数量。
  - 执行 `Create Release` 创建快照，再由管理员执行 `Activate`。
  - 未审核的候选知识不会进入正式问答。

- [ ] **第 7 步：问答验收**
  - 使用预先准备的 10～20 个问题测试。
  - 每个回答检查：是否基于 active release、是否有引用、引用能否定位到原文、是否承认证据不足、是否混淆术语。
  - 将错误分为：资料缺失、解析错误、抽取错误、审核错误、检索错误或回答表达错误。

- [ ] **第 8 步：运行自动验收**
  - 执行 `env UV_CACHE_DIR=.uv-cache uv run python scripts/run_v1_acceptance.py`。
  - 自动测试通过只代表系统流程正常；真实资料的引用准确性仍需专家人工确认。

## 三、判断系统正常运行的最低标准

- [ ] 健康检查返回 `status: ok`。
- [ ] PDF/Markdown 上传后能看到文档记录和非空分块。
- [ ] 配置 MiMo 后能产生待审核候选知识，失败时页面能显示错误原因。
- [ ] 审核通过的知识可以创建并激活 release。
- [ ] 聊天页面只使用 active release，并返回可定位的文献引用。
- [ ] 未审核内容不会出现在正式回答中。
- [ ] 自动验收脚本通过，管理页可查看失败任务和审计记录。
- [ ] API 重启后是否需要保留全部文档元数据、审核记录和 release 已确认并处理。

## 四、当前限制和注意事项

- 当前 PDF 解析主要适合带文本层的 PDF；扫描件、复杂表格和复杂中文排版需要用真实样例继续评估 OCR/版面解析。
- 当前业务元数据主要使用内存仓库。API 进程重启后，文档列表、审核记录和 release 等运行数据可能丢失；原始文件虽可能仍在本地对象存储，但不能把当前版本当作生产级持久化系统。
- 如需稳定现场演示，应先确认是否要求“重启后恢复数据”；若要求，需要再实现持久化仓库和可重置的演示数据。
- 当前用途是内部科研证据辅助，不作为诊疗建议，也不应自动发布未经专家审核的医学结论。

## 五、首批交付给开发侧的最小资料包

- [ ] 5～10 份优先级最高、允许使用的真实 PDF/Markdown。
- [ ] 一份对应的文献说明表。
- [ ] 可用的 MiMo base URL、model ID，并在本机安全配置 API key。
- [ ] 10 个验收问题及对应期望引用或“证据不足”判断。
- [ ] 一名审核人和一名发布管理员。
